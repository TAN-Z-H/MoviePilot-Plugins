# OneBot v11 通知（MoviePilot V3 插件）

通过 [OneBot v11](https://github.com/botuniverse/onebot-11) 协议（[NapCat](https://napneko.github.io/) 实现）
把 MoviePilot 的通知推送到 QQ 私聊与群聊。插件订阅宿主通知事件，因此**入库整理、
下载、订阅、站点、媒体服务器、插件、系统错误**等场景的通知都会一并转发。

- 插件 ID：`OneBotMsg`
- 源码目录：`plugins.v3/onebotmsg/`
- 测试目录：`tests/v3/onebotmsg/`
- 版本：`1.2.0`，要求 `MoviePilot >= 3.0.0`
- 依赖：无（仅使用 Python 标准库与宿主已提供的 pydantic / fastapi）
- 图标：使用 NapCat 官方 Logo 外链，仓库不附带图标文件（版权归 NapCat 项目所有）

## 版本亮点

| 版本 | 能力 |
| --- | --- |
| **1.2.0** | 🖼 **图文同条**：海报与通知文字放进同一条消息（QQ 里显示在同一个气泡），另有「图片在下」与「分开发送」可选；修复群 @ 取到布尔值、以及 `群:` 全/半角冒号识别问题 |
| 1.1.0 | 🎴 卡片排版（按显示宽度对齐）· 🖼 图片 URL / base64 / 本地路径自动降级 · 🔌 正向 WebSocket 传输（可收投递回执）· 🧩 NapCat 扩展 API（合并转发 / 表情回复 / 能力探测）· 🔍 预览与探测按钮 |
| 1.0.0 | 首个版本：订阅宿主通知事件转发到 OneBot v11，多目标、类型过滤、去重限流重试 |

## 1. 前置条件：配置 NapCat

1. 部署 NapCat 并登录机器人 QQ。
2. 打开 NapCat 的 **WebUI → 网络配置**，按所选连接方式启用其一：

   | 连接方式 | NapCat 侧要启用的服务 | 插件里填的地址 |
   | --- | --- | --- |
   | HTTP 正向接口（默认） | **HTTP 服务器**，端口默认 `3000` | `http://<host>:3000` |
   | 正向 WebSocket | **WebSocket 服务器** | `ws://<host>:<端口>`（也可填 `http://` 同端口，插件会自动转换） |

3. **Host 必须填 `0.0.0.0`**。填成宿主机局域网 IP（例如 `192.168.3.22`）会让 NapCat 在容器里
   `bind` 一个不存在的地址，日志报 `EADDRNOTAVAIL: address not available`，插件侧表现为
   `Connection reset by peer`。
4. 建议设置 **Token**，并与插件配置保持一致。

> 插件只用 OneBot v11 的**动作调用**能力（发消息 / 扩展动作）。
> 若还需要接收 QQ 消息做交互，可在 NapCat 里额外配反向 WS，本插件不占用它。

## 2. 安装

插件按 MoviePilot 插件仓约定落位：

```
MoviePilot-Plugins/
├── plugins.v3/onebotmsg/
│   ├── __init__.py        # 插件主类 OneBotMsg
│   ├── onebot.py          # OneBot HTTP 客户端、限流与去重
│   ├── transport.py       # 传输抽象：HTTP / 正向 WebSocket
│   ├── ws.py              # 纯标准库 WebSocket 实现（含测试用回环服务端）
│   ├── render.py          # 通知排版（卡片 / 紧凑 / 原始）
│   ├── napcat.py          # NapCat 扩展 API 与消息段、图片处理
│   ├── pyproject.toml     # 依赖清单（本插件无额外依赖）
│   └── README.md          # 本文档
├── tests/v3/onebotmsg/
│   └── test_plugin.py     # 回归测试
└── package.v3.json        # 索引，须登记 OneBotMsg 条目
```

索引中的 `version` 必须与插件类的 `plugin_version` 一致，且 `history` 首项为当前版本。

### 2.1 本地目录加载

在 MoviePilot 的 `.env` 中配置本地插件仓库路径，便于边改边测：

```dotenv
PLUGIN_LOCAL_REPO_PATHS=/path/to/MoviePilot-Plugins
PLUGIN_AUTO_RELOAD=true
DEBUG=true
```

随后在 **设定 → 插件市场** 中安装「OneBot v11 通知」。

## 3. 配置说明

### 3.1 基础

| 配置项 | 说明 |
| --- | --- |
| 启用插件 | 总开关。未启用时不接收任何通知 |
| OneBot 地址 | NapCat 的 HTTP 或 WS 服务器地址 |
| Access Token | 与 NapCat 保持一致，未设置则留空 |
| 连接方式 | `HTTP 正向接口` 或 `正向 WebSocket` |
| 默认推送目标 | 每行一个；**裸数字按私聊**，群号必须加 `群:` 或 `group:` 前缀 |
| 用户定向推送 | 按 MoviePilot 用户名定向，未命中的用户回落默认目标 |

### 3.2 排版

| 配置项 | 说明 |
| --- | --- |
| 排版样式 | `卡片`（带边框，等宽字体最好看）/ `极简`（`✅ 标题` + `· 字段`，**配海报推荐**）/ `紧凑` / `原始` |
| 卡片最大宽度（列） | 默认 34；中文按 2 列计，手机端建议 30~36 |
| 标题前缀 | 给所有标题加统一前缀，例如 `[MoviePilot]` |
| 发送方式 | `单条消息` / `合并转发` / `自动`（明细多时用合并转发） |
| 自动转合并转发的明细行数 | 「自动」模式的阈值，默认 5 |
| 单条消息最大长度 | 超出后按行分段，默认 1200 |
| 附带链接 | 在卡片底部附上通知链接 |
| 群消息 @ 用户 | 群消息在正文前插入 `at` 段 |
| 发送成功后贴表情回复 | 用 NapCat `set_msg_emoji_like` 给刚发的消息贴 👍，失败自动忽略 |
| 附带海报图片 | 通知带图时一并发送海报 |

三种样式的实际效果可以在配置页点「**预览排版效果**」直接看到。

**卡片样式**（推荐）：

```
╭─────────────────────────╮
│ ✅ 整理入库 某剧 (2024) │
├─────────────────────────┤
│ 季集  S01E03            │
│ 分类  电视剧/欧美剧     │
│ 体积  2.41 GB           │
├─────────────────────────┤
│ http://mp/#/media       │
╰─────────────────────────╯
```

**紧凑样式**：

```
✅ 整理入库 某剧 (2024)
· 季集：S01E03
· 分类：电视剧/欧美剧
```

### 3.3 图片（重点：发不出来 / 想嵌进通知里就改这里）

| 配置项 | 说明 |
| --- | --- |
| 图片发送方式 | 见下表（决定图片数据怎么送到 NapCat） |
| 图文组合方式 | `图文同条`（默认，海报嵌在通知气泡里）/ `分开发送` |
| 同条时图片位置 | `图片在上`（海报 + 信息卡片）/ `图片在下` |
| base64 体积上限（MB） | 超过则退回 URL 方式，默认 3 |

| 发送方式 | 行为 | 适用场景 |
| --- | --- | --- |
| `自动`（默认） | 先按 URL 发；图片可读时同时准备 base64，URL 那次失败就用 base64 重试 | 绝大多数情况 |
| `仅 URL 外链` | 只把图片 URL 交给 NapCat，由 NapCat 自己去下载 | NapCat 能直连外网、且图片源允许其抓取 |
| `仅 base64 内嵌` | 插件下载图片后以 `base64://` 内嵌发送 | **NapCat 在受限网络/容器里抓不到外链时最稳** |
| `仅本地路径` | 下载到插件数据目录，把本地路径交给 NapCat | MoviePilot 与 NapCat 挂载了同一目录 |
| `不发送图片` | 只发文字与链接 | 只想省流量 |

#### 图文同条（1.2.0 默认）

图片段与文本段放进**同一条消息**，QQ 会把它们渲染在同一个气泡里，
海报就成了通知的一部分，不再出现「一条文字 + 一条图片」两条消息：

```
╭──────────────────────╮
│  [ 海 报 图 片 ]     │   ← 同一个气泡
│ ✅ 整理入库 某剧     │
│ · 季集：S01E03       │
│ · 分类：日番         │
│ · 体积：879.02 MB    │
╰──────────────────────╯
```

搭配建议：

- **配海报用「极简」样式最协调**——极简与紧凑都是 `✅ 标题` + `· 字段` 的纯文本行，
  不依赖等宽字体对齐，气泡里图文挨着不会显得错位；
- 「卡片」样式靠空格对齐边框，QQ 气泡是比例字体，**单独发时好看，和图片同条时边框会歪**，
  所以同条场景建议极简或紧凑；
- 文本过长被分成多段时会**自动退回分开发送**，避免图片挂在第一段、后文割裂。

#### 为什么图片会发不出来

OneBot 的 `image` 段把 URL 交给 NapCat 后，**由 NapCat 去下载**。
如果 NapCat 所在容器访问不到该图源（网络策略、CDN 防盗链、超时），消息里就只剩文字。
换成 `base64 内嵌` 可以绕开这个问题——图片数据随消息一起送到 NapCat，不再需要它出网。

NapCat 支持的资源形式（官方文档「资源与消息 ID 设计说明」）共 5 种，
本插件的三种方式分别对应其中的 `http/https`、`base64://` 与 `path`。

另外点配置页的「**探测 NapCat 能力**」可以直接看到：
NapCat 版本、是否允许发送图片（`can_send_image`）、当前图片方式，用于快速定位。

### 3.4 推送范围与稳定性

| 配置项 | 说明 |
| --- | --- |
| 推送的消息类型 | 勾选需要转发的场景；**未勾选任何场景时不推送通知** |
| 去重时间窗口（秒） | 窗口内相同通知只发一次，默认 20，填 0 关闭 |
| 每秒最大发送条数 | 客户端侧令牌桶限流，默认 3 |
| 失败重试次数 | 网络类失败按指数退避重试，默认 2 |

### 3.5 目标格式

群号与 QQ 号在 OneBot 中都是纯数字，无法自动区分，因此**群目标必须显式加前缀**：

```
123456789          # 私聊，发送给 QQ 123456789
private:123456789  # 同上，显式声明
群:987654321       # 群聊
group:987654321    # 同上
```

多目标可以写在多行，也可以用逗号分隔。

### 3.6 用户定向推送

支持两种写法，可混用：

```
admin=123456789
alice=111111,群:222222
```

```json
{"admin": "123456789", "alice": ["111111", "群:222222"]}
```

未命中的用户（或系统级、无关联用户的通知）一律回落到「默认推送目标」。

## 4. 功能一览

### 4.1 全场景通知转发

插件订阅宿主 `EventType.NoticeMessage`，该事件由 `ChainBase.post_message()` 在
**所有**通知场景下发，事件数据包含：

```text
channel, source, mtype(type), ctype, title, text, image, link,
userid, username, targets, buttons, ...
```

因此 MoviePilot 的以下场景都会转发（**默认勾选前六项**，可在配置中按需裁剪）：

| 场景 | 类型名 | 默认 |
| --- | --- | --- |
| ✅ 整理入库 | `Organize` | 开启 |
| 📥 资源下载 | `Download` | 开启 |
| 🔔 订阅 | `Subscribe` | 开启 |
| 🛠️ 手动处理（需人工介入的失败） | `Manual` | 开启 |
| 🌐 站点 | `SiteMessage` | 开启 |
| 🧩 插件 | `Plugin` | 开启 |
| 🎬 媒体服务器（播放/入库） | `MediaServer` | 关闭 |
| 🤖 智能体 | `Agent` | 关闭 |
| 📢 其它 | `Other` | 关闭 |

未勾选任何场景即完全不推送。另外，如果宿主中配置了 QQ 通知渠道且**全部处于禁用
状态**，插件会自动跳过转发，避免与用户在 MoviePilot 中的关闭意图冲突。

### 4.2 入库通知增强

除宿主通知外，插件额外订阅：

- `EventType.TransferComplete`：整理完成
- `EventType.TransferFailed`：整理失败

事件中携带宿主通知未覆盖的字段时，插件补充一张结构化卡片，包含**季集、分类、
媒体身份（`media_source` + `media_id`）、文件数、体积、目标路径、整理方式、
失败阶段与建议动作**。事件缺少可用标题时不会构造通知，避免与宿主原生通知重复刷屏。

### 4.3 两种传输的差别

| 能力 | HTTP 正向接口 | 正向 WebSocket |
| --- | --- | --- |
| 调用任意 OneBot / NapCat 动作 | ✅ | ✅ |
| 连接开销 | 每次动作新建连接 | 复用一条长连接 |
| `message_sent` 投递回执 | ❌ 收不到 | ✅ 能收到，可确认消息真的发出 |
| 需要的 NapCat 配置 | HTTP 服务器 | WebSocket 服务器 |

WS 模式下，状态卡片里的「投递回执」计数就是 NapCat 回推的 `message_sent` 条数——
它比「接口返回 ok」更接近事实。

### 4.4 NapCat 扩展 API

| 动作 | 插件里的用法 |
| --- | --- |
| `send_forward_msg` | 「发送方式 = 合并转发」时使用；失败自动降级为单条卡片 |
| `set_msg_emoji_like` | 「发送成功后贴表情回复」开启时使用；不支持时静默忽略 |
| `can_send_image` / `get_version_info` | 「探测 NapCat 能力」按钮 |
| `_send_group_notice` / `upload_group_file` / `send_poke` | 已封装在 `napcat.py`，可在工作流或自定义代码里调用 |

### 4.5 稳定性设计

- **发送队列**：宿主事件线程只做入队，真正的发送由独立的 `OneBotMsgSender`
  守护线程串行执行，保证顺序且不阻塞事件总线。
- **自动分段**：超过「单条消息最大长度」时按**行边界**切分（不会把卡片边框切断），
  并在每段前标注 `(1/3)`。
- **限流**：令牌桶控制每秒发送条数，缓解 NapCat 风控。
- **去重**：宿主按 `admin/user/all` 路由会重复派发同一条通知，插件按
  「类型 + 标题 + 正文 + 图片」在时间窗口内去重。
- **失败重试**：连接失败/超时按 `0.6s → 1.2s → 2.4s` 指数退避重试；
  协议层失败（`retcode != 0`）不重试。
- **图片降级**：URL 发不出去时自动尝试 base64；都失败只损失图片，文字照常送达。
- **不重复推送**：通知已指定其它渠道、或宿主 QQ 渠道被禁用时自动跳过。

## 6. 插件 API

所有接口均需登录态（`auth: bear`），路径前缀为 `/api/v1/plugin/OneBotMsg`。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/test` | 发送测试通知，返回值里附带渲染后的卡片预览 |
| POST | `/push` | 推送自定义通知，供工作流或外部调用 |
| GET | `/status` | 查询运行状态 |
| GET | `/preview` | 预览三种排版样式的渲染结果（**不发送**） |
| GET | `/probe` | 探测 NapCat 版本、图片发送能力与当前图片方式 |

`POST /push` 请求体：

```json
{
  "title": "自定义标题",
  "text": "季集：S01E01\n分类：电视剧",
  "image": "https://example.com/a.jpg",
  "link": "http://moviepilot/#/media",
  "emoji": "🎯",
  "target": "群:987654321",
  "send_mode": "forward",
  "style": "card"
}
```

`target` / `send_mode` / `style` 均为可选，用于临时覆盖插件配置。

## 7. 排查

| 现象 | 排查方向 |
| --- | --- |
| 测试通知报「连接失败」 | 地址/端口是否正确、NapCat 是否启动、容器网络是否互通 |
| `Connection reset by peer` | NapCat 的 Host 多半填成了具体 IP：改成 `0.0.0.0` 并重启 NapCat |
| 报 `HTTP 401/403` | Access Token 与 NapCat 不一致 |
| 报 `retcode=...` | NapCat 侧拒绝，例如未登录、目标非好友、群号错误 |
| **文字到了、图片没到** | 把「图片发送方式」改成 `仅 base64 内嵌`；或点「探测 NapCat 能力」看 `can_send_image` |
| 只有部分目标收到 | 单条消息是否过长；查看日志中的 `成功 x/y` |
| 完全收不到通知 | 插件是否启用；消息类型是否被过滤；宿主场景开关是否被关闭；日志级别调为 `DEBUG` |
| 收到重复消息 | 同时启用了宿主 QQ 渠道与本插件，二选一即可 |
| 合并转发不可用 | 该动作需要较新 NapCat；插件会自动降级为单条卡片，不影响通知 |

日志关键字：`OneBot v11 通知插件`、`OneBot 通知已发送`、`OneBot 通知发送失败`。

## 8. 自测

测试位于 `tests/v3/onebotmsg/test_plugin.py`，按仓库约定通过生产命名空间
`app.plugins.onebotmsg` 导入插件与子模块，只 mock 对外 HTTP 调用；
**WebSocket 那一层用真实回环服务端做端到端验证**（握手、掩码、分片、echo 派发、
Token 鉴权），不是只断言形状。

```bash
# 仓库统一门禁（与 CI 一致，需要 MoviePilot 后端与 .venv）
<workspace>/.venv/bin/python tests/run.py

# 只跑本插件
<workspace>/.venv/bin/python -m pytest tests/v3/onebotmsg
```

覆盖范围：协议帧编解码、WS 端到端、传输抽象、排版宽度与四种样式、字段解析、
图片候选与降级、**图文同条/分开发送/图片位置**、目标前缀（全半角冒号）、
目标路由、类型过滤、转发端到端、合并转发与降级、表情回复、能力探测、命令回执、
生命周期与表单一致性。

> 缺少 MoviePilot 后端时，测试会降级为内置 stub 自检；**正式提交与 CI 必须走
> 真实宿主**。测试不会把插件目录加入 `sys.path`，避免同一源码被双重导入；
> 按仓库约定只提供 pytest 用例，不提供独立的 `__main__` 入口。

在真实 MoviePilot V3 宿主中安装后，还需确认插件能正常加载、启用、禁用与重载，
`DEBUG=true` 时不产生旧导入路径告警，并在页面上点「发送测试通知」验证 QQ 可达。
